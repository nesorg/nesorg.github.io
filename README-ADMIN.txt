NARA EDUCATIONAL SOCIETY — WEBSITE ADMIN

1. Upload CMS-Admin.html to the root of your nesorg/nesorg.github.io repository. This one admin file contains its code, page templates and default images. You can connect your repository later from Publish website. For a full manual website install, upload every file from this ZIP to the same repository root. Keep index.html and CMS-Admin.html together. Public pages retain the supplied website's design and content.
2. Open https://nesorg.github.io/CMS-Admin.html after uploading CMS-Admin.html to your website repository root. Sign in with the username/password provided in the separate PRIVATE ANES-Admin-Login.txt file. Never upload that private file. Local drafting, preview, backups and ZIP downloads work without connecting GitHub.
3. Edit Announcements, Events, Team members, Gallery, Homepage cards, individual page text/images/buttons, SEO, global contacts and the menu. Save each form. Saved drafts survive reloads on that browser/device.
4. To publish directly, open Publish website. Enter your repository (nesorg/nesorg.github.io is prefilled), branch (usually main), and website folder (blank for this site root). Use a fine-grained GitHub token restricted to this repository, with Contents: read and write permission. The account needs repository write access. The token and connection baseline are saved encrypted in this browser after a successful connection. They are never included in JSON backups, website ZIPs or public content.
5. Connect GitHub once in the updated admin. Refreshes and later sign-ins automatically reconnect using the encrypted saved connection. Disconnect & forget removes it. Clearing browser data, using another browser/device, or token expiry/revocation requires connecting again. A network error keeps the saved connection and draft; Retry saved connection tries again. If there is a published content file, Load latest website loads that version; a restore point is made before replacing an unpublished draft. When installing the admin for the first time, the current draft starts with the supplied ZIP's content.
6. Click Review changes, inspect the file list, then Publish changed files. The panel compares the repository against the version you loaded, preserves unrelated files and saves changes in a single no-force commit. A conflict keeps the local draft. GitHub Pages deploys after the commit is saved. Your repository must already have its initial commit and GitHub Pages configured for the chosen branch/folder.
7. Alternatively, Download website produces a complete ZIP with rendered HTML, content, images and the admin. Upload those files using your usual hosting method.
8. Backups & restore exports/imports Nara JSON backups including compressed uploads. Keep a backup outside your browser. Browser drafts are not permanent hosting; GitHub publication or an exported backup provides the durable copy.

AUTOMATIC IMAGE COMPRESSION: all single photo uploads (team, records, homepage cards), website page images, shared logo images and bulk gallery uploads are compressed automatically. The panel displays original and saved sizes in KB and the reduction percentage. It waits for compression before saving or publishing. Choose several JPG/PNG/WebP photos and a category, then Upload photos. Each photo is reduced to at most a 1,800-pixel edge and encoded efficiently. Already smaller source files are retained when recompression would grow them. This keeps images clear while reducing transfer size. You can edit names, captions, ALT text, categories, visibility and order.

EVENTS: upcoming events appear on Events and Home. The existing informational event/program descriptions remain editable in Website pages. When no upcoming events exist, the original informational card is shown.

TEAM: edit names, roles, photos and biographies once for Team and Home leadership cards. The separate Founder & Chief Patron story and portrait are also editable through Website pages on Home and About.

SHARED FIELDS: header/footer text and links marked SHARED update in their matching positions across pages. Global contact settings update WhatsApp links, email links, telephone links, contact-form destinations and vCard details. The existing contact form continues sending via WhatsApp/email; this package does not add a separate message inbox.

PREVIEW: previews display the saved draft in a sandbox. WhatsApp, email and forms may be restricted inside the sandbox. They operate normally on the exported/public website. The admin runs directly on your own nesorg.github.io site. It does not require a ChatGPT login or a separate hosting service.

LOGIN: no Firebase, Supabase or external login service is used. Each delivered package has its own initial username/password in the separate private login file. Log out using the top button; the session also locks after 30 minutes of inactivity. Security & login lets you update the username/password after confirming the current password. Use at least 12 characters for a new password. After changing login details, publish the updated admin or download CMS-Admin.html from that section and replace the hosted file. Until the file is replaced, other devices still use the old hosted login. Keep your current login and a content backup outside the browser. There is no email reset service.

LOCAL DATA: saved drafts and restore points are encrypted with AES-GCM in the browser. The password is checked with a salted PBKDF2-SHA256 verifier and unwraps the local encryption key. A tab session keeps its key only until logout/expiry or the tab closes. Existing unencrypted drafts are migrated after the first successful login. JSON content backups contain your website content and uploaded photos; keep them private. They never contain your login password or GitHub token.

ACCESS: GitHub Pages serves static files, including the admin application. Browser login controls the normal admin workflow and local encrypted drafts; it is not server-side access control for the hosted HTML. Only a verified GitHub writer token can publish to the repository. The generated HTML contains a salted verifier, not the plaintext login password. Separate browser profiles/devices keep separate drafts. No public shared default password is shipped.

The panel includes fflate (MIT) for ZIP export. Its license is included in the package.
